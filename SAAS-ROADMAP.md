# SaaS Roadmap — From Journal to Product

**Current status:** Stage 0 — concept documentation.  
**Rule:** advance only when the previous stage has evidence. No stage is marked complete by intention alone.

## Stage 0 — Identity and product definition

- [x] Record the human owner and AI collaborator accurately.
- [x] Explain why the project exists.
- [x] Separate the public journal from the future product.
- [x] Document the proposed problem, users, and MVP direction.
- [ ] Owner review of this product foundation.

## Stage 1 — Problem validation

- Interview a small, relevant group of independent builders and small teams.
- Ask how they currently preserve AI-assisted project decisions and lessons.
- Identify the highest-cost recurring problem.
- Compare existing workflows and tools.
- Record evidence, objections, and reasons not to build.
- **Exit gate:** a clearly defined user segment and repeated, evidence-backed problem.

## Stage 2 — MVP specification

- Define the first user journey and data model.
- Specify workspaces, projects, decisions, lessons, milestones, sources, actions, and publication states.
- Define private-by-default access and export.
- Create wireframes and acceptance criteria.
- Complete a threat model and data-retention plan.
- **Exit gate:** an owner-approved, testable MVP specification.

## Stage 3 — Free prototype

- Build the smallest useful single-user prototype.
- Support manual capture, search, evidence links, status labels, and Markdown/JSON export.
- Add tests for permissions, export, and data integrity.
- Use only free services or local development during this phase.
- **Exit gate:** working prototype demonstrated with test data; no real user data until safeguards are reviewed.

## Stage 4 — Private beta

- Invite a small number of consenting testers.
- Measure capture effort, retrieval usefulness, trust, and repeat usage.
- Provide deletion/export controls and a clear feedback route.
- Fix privacy, usability, and reliability issues before expanding.
- **Exit gate:** repeated use and evidence of meaningful value.

## Stage 5 — SaaS readiness

- Select a sustainable hosting and database model.
- Implement authentication, workspace isolation, authorization, backups, monitoring, rate limits, and incident handling.
- Review privacy terms, data processing, retention, and applicable legal obligations.
- Establish transparent operating costs and support procedures.
- **Exit gate:** security and operational review completed; owner approves launch.

## Stage 6 — Commercial validation

- Test willingness to pay before setting prices.
- Compare free, individual, and team packaging.
- Publish accurate terms, limits, and support commitments.
- Do not introduce paid services or commitments without explicit owner approval.
- **Exit gate:** evidence-backed pricing and sustainable unit economics.

## Current limitations

No application code, production service, user accounts, billing, automated chat connector, customer base, revenue, or production deployment is claimed by this roadmap. GitHub documentation is not itself a SaaS product.
